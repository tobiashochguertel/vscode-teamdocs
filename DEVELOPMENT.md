# Development

How to work on this fork: branches, patches, changelog, releases.

## Branches

- **`dev.patch`** — the develop branch. All fork work lands here.
- **`main`** — tracks upstream release tags; stable lane patches get promoted to.
- **`feature/*`** — short-lived branches off `dev.patch` that produce `.patch` files.
- **`feat/*`** — branches off upstream for changes meant as upstream PRs.

## Fork strategy

Fork-owned changes to upstream files live as `.patch` files in `.github/patches/` and are
re-applied by the daily sync (`sync-upstream-and-fix.yml`). New files are committed directly.
Full details: [`.github/FORK-STRATEGY.md`](.github/FORK-STRATEGY.md).

## Making a change to an upstream file (incl. README, CHANGELOG, package.json)

```bash
git checkout -b feature/my-change dev.patch
# edit files, commit
fork-genpatch generate --branch feature/my-change \
  --output .github/patches/NNN-my-change.patch
git checkout dev.patch && git apply .github/patches/NNN-my-change.patch
git add -A && git commit
```

## Changelog

`CHANGELOG.md` is generated by **git-cliff** (`cliff.toml`, conventional commits) — but it is a
patched file, so regenerate on a feature branch and capture via a patch:

```bash
git checkout -b feature/changelog dev.patch
mise run changelog            # regenerates ## [Unreleased]
git commit -am "docs: update changelog"
fork-genpatch generate --branch feature/changelog --output .github/patches/NNN-changelog.patch
git checkout dev.patch && git apply .github/patches/NNN-changelog.patch
git add -A && git commit
```

Preview without writing: `mise run changelog:preview`.

## Dependabot PRs

Never merge them directly — the next sync reverts them. The `dependabot-to-patch.yml`
workflow converts incoming PRs to `.patch` commits on `dev.patch` and closes them
automatically. If it reports a conflict, rebase the PR (`@dependabot rebase`) or integrate
manually via the patch workflow above.

## Releasing

Releases are cut from `dev.patch`: create a GitHub release (`vX.Y.Z`) → `publish.yml` pushes
the `.vsix` to Open VSX (VS Code Marketplace re-enables once Microsoft's rate-limit issue is
resolved). Before cutting a release: bump `version` in `package.json` via a patch (see
`003`/`005` for the pattern) and regenerate the changelog.
